### Detalle (medio/alto/crítico)

#### A-001 — CI roto (PHP 8.3 vs Symfony 8.1)

- **Evidencia:** `gh run view 28826364884 --log-failed` → `symfony/var-dumper v8.1.1 requires php >=8.4.1 -> your php version (8.3.32)`. Últimos 4 pushes a `main` fallaron.
- **Impacto:** Regresiones no detectadas; PRs sin gate; `composer test` / Scribe no corren en CI.
- **Recomendación humana:** Actualizar workflow a `php-version: '8.4'` (verificar PHP VPS CloudPanel) **o** fijar Symfony 7.x compatible con 8.3. Alinear `composer.json` `"php"` con la decisión.

#### A-002 — Webhooks Green API incompatibles

- **Evidencia:**
  - `VerifyWebhookSignature` exige header `X-Webhook-Signature` HMAC con `WEBHOOK_SECRET`.
  - `WebhookIdempotency` exige `X-Event-Id`.
  - `.env.example` define `GREEN_API_WEBHOOK_TOKEN` pero no se usa en middleware.
  - Tests (`WebhookVerificationTest.php`) validan el contrato HMAC interno, no el de Green API.
  - `IncomingWebhookController` sí maneja `stateInstanceChanged` (commit `8aab7d9`) pero nunca recibe payloads reales si middleware rechaza.
- **Impacto:** Transición `waiting_qr` → `authorized` depende de polling manual (`InstanceStateSyncService`) o scripts ops; webhooks Green no operativos.
- **Recomendación humana:** Adaptar middleware a Bearer token de Green API; idempotencia por hash de payload o `idMessage`; actualizar contrato en `waapi-api-contract.md`.

#### A-003 — Migración comercial pendiente en VPS

- **Evidencia:** `2026_07_06_120000_add_commercial_fields_to_core_tenants_table.php` añade `commercial_status`, `plan_*`, `demo_*`, `messages_monthly_limit`, `last_api_activity_at`, `first_message_sent_at`.
- **Impacto:** Framework `9ae594e` espera campos comerciales; sin migrate, PATCH tenant / account status pueden fallar o devolver nulls.
- **Recomendación humana:** Deploy rutinario + `php artisan migrate --force` + `php artisan tenants:sync-client-permissions` para tokens demo existentes.

#### A-005 — Tests faltantes en endpoints nuevos

- **Evidencia:** `UsageTest.php` cubre GET `/usage`; no hay tests para `POST /account/status`, `TrackTenantActivity`, ni flujo `InstanceStateSyncService` en envío.
- **Impacto:** Regresiones en churn/retention no detectadas hasta smoke manual.
- **Recomendación humana:** Añadir `AccountStatusTest.php` con tenant demo, límites y expiración.
