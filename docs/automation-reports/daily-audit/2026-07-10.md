### Detalle (medio/alto/crítico)

#### A-001 — CI roto (Symfony 8.1 vs PHP 8.3)

- **Evidencia:** GitHub Actions run `28895273158` (push `ab6c83a`, 2026-07-07): 19 paquetes Symfony v8.1.x requieren `php >=8.4.1`; workflow `php-version: '8.3'`.
- **Impacto:** Ningún PR puede validarse en CI. Regresiones no detectadas automáticamente.
- **Recomendación humana:** Opción A: actualizar workflow + `composer.json` a `^8.4`. Opción B: `composer update` con constraint Symfony `^7.4` y regenerar lock. Verificar PHP en VPS CloudPanel antes de decidir.

#### A-002 — Webhooks Green API incompatibles

- **Evidencia:**
  - `ProvisionGreenInstanceJob` líneas 68–73: `setSettings(['webhookUrlToken' => config('services.green_api.webhook_secret'), ...])`
  - `VerifyWebhookSignature`: exige header `X-Webhook-Signature` = HMAC-SHA256 del body
  - `WebhookIdempotency`: exige header `X-Event-Id`
  - Contrato `waapi-api-contract.md` §Webhooks documenta HMAC + X-Event-Id (diseño genérico, no Green API nativo)
- **Impacto:** Eventos `stateInstanceChanged` de Green API no actualizarán `int_instancias.status` en producción. QR → authorized puede no reflejarse vía webhook (solo polling manual).
- **Recomendación humana:** Implementar middleware dual: validar `webhookUrlToken` (query param o Bearer) para Green API + mantener HMAC opcional para futuros proveedores. Adaptar idempotencia a campo Green API (`timestamp` + `idMessage` o similar). Actualizar contrato.

#### A-004 — Migración commercial fields pendiente en VPS

- **Evidencia:** `2026_07_06_120000_add_commercial_fields_to_core_tenants_table.php` añade `commercial_status`, `plan_slug`, `demo_expires_at`, etc. Último deploy documentado G0.1 (`0da065b`, 2026-07-02) solo menciona `int_mensajes`.
- **Impacto:** `PATCH /tenants` con campos comerciales fallará si columnas no existen. Framework churn dashboard (`c3b6383`) depende de estos campos.
- **Recomendación humana:** SSH → `php artisan migrate:status` → aplicar si pendiente → `supervisorctl restart lebytek-api-horizon`.
