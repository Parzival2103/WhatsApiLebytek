### Detalle (medio/alto/crítico)

#### A-001 — CI roto por drift PHP / Symfony

- **Evidencia:** Log Actions run `ab6c83a`: `symfony/http-foundation v8.1.1 requires php >=8.4.1 -> your php version (8.3.32) does not satisfy that requirement.` Cinco runs consecutivos en `main` con `conclusion: failure`.
- **Impacto:** Ningún PR/commit pasa CI; regresiones no detectadas automáticamente; riesgo en futuros deploys con `composer update`.
- **Recomendación humana:** Subir workflow a PHP 8.4.1+ **y** verificar VPS; o ejecutar `composer update` con platform PHP 8.3 para forzar Symfony 7.x y commitear lock.

#### A-002 — Webhooks Green API incompatibles con middleware

- **Evidencia:**
  - `ProvisionGreenInstanceJob` L68-72: `webhookUrlToken` = `WEBHOOK_SECRET`
  - Green API docs: envía `Authorization: Bearer {token}` cuando `webhookUrlToken` está configurado
  - `VerifyWebhookSignature`: exige header `X-Webhook-Signature` HMAC-SHA256
  - `waapi-api-contract.md` L355 documenta HMAC (no coincide con Green API real)
- **Impacto:** Webhooks de Green API reciben 401; `stateInstanceChanged` en `IncomingWebhookController` no se ejecuta; estado de instancias puede desincronizarse respecto a Green API.
- **Recomendación humana:** Implementar validación dual (Bearer token **o** HMAC si se mantiene para otros emisores); alinear contrato y tests; smoke en VPS con webhook real.

#### A-003 — Riesgo deploy `composer install` en VPS

- **Evidencia:** `composer.lock` → `symfony/http-foundation v8.1.1`; `composer.json` → `"php": "^8.3"`; `CONTEXT.md` documenta PHP 8.3+.
- **Impacto:** Deploy rutinario (`git pull` + `composer install`) puede fallar si VPS tiene PHP 8.3.
- **Recomendación humana:** Verificar `php -v` en VPS `lebytek-api`; no desplegar hasta resolver A-001.

#### A-004 — Smoke E2E incompleto

- **Evidencia:** `VPS_CHECKLIST.md` pasos 2–5 sin marcar; paso 3 (`POST /messages` → móvil) bloquea go-live fase 3.
- **Impacto:** Producto no validado end-to-end; DNS cutover prohibido por checklist propio.
