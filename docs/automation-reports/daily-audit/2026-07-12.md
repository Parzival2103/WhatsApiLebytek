### Detalle (crítico / alto / medio)

#### A-001 — Webhook auth incompatible con Green API

- **Evidencia:** `ProvisionGreenInstanceJob` configura `webhookUrlToken` con `WEBHOOK_SECRET`. Green API documenta envío `Authorization: Bearer {token}`. `VerifyWebhookSignature` exige `X-Webhook-Signature` HMAC SHA-256 del body.
- **Impacto:** Instancias provisionadas no pueden notificar cambios de estado a la API. Smoke E2E fase 2a (QR, mensajes) bloqueado en producción real.
- **Recomendación humana:** Extender middleware para aceptar Bearer **o** alinear contrato con proxy edge que traduzca headers.

#### A-002 — Idempotencia webhook requiere header inexistente

- **Evidencia:** `WebhookIdempotency` aborta 422 si falta `X-Event-Id`. Spec en `docs/superpowers/plans/2026-07-02-integration-phase4-5.md` menciona fallback por hash de payload — no implementado.
- **Impacto:** Incluso con firma corregida, webhooks seguirían fallando en idempotencia.
- **Recomendación humana:** Derivar `eventId` de `idMessage`, `typeWebhook`+timestamp o hash del body.

#### A-003 — CI roto (PHP platform mismatch)

- **Evidencia:** GitHub Actions run `29183105951` (merge PR #9, 2026-07-12T06:44Z): `symfony/console v8.1.1 requires php >=8.4.1 -> your php version (8.3.32)`.
- **Impacto:** Ningún commit en `main` pasa CI desde el lockfile actualizado (commit `49e204b`). Regresiones no detectadas automáticamente.
- **Recomendación humana:** Subir CI a PHP **8.4** (alineado con README/VPS) **o** regenerar lock en 8.3 con Symfony 7.4.x.

#### A-004 — Horizon provisioning sin supervisor en entornos

- **Evidencia:** `config/horizon.php` L241-252 define `supervisor-provisioning`; `environments.production` (L256-271) solo incluye default/transactional/campaigns.
- **Impacto:** `ProvisionGreenInstanceJob` y `DeleteGreenInstanceJob` en cola `provisioning` pueden acumularse sin procesar si Horizon es el único worker.
- **Recomendación humana:** Añadir `supervisor-provisioning` a production/local/testing; verificar en VPS con `php artisan horizon:status` y cola Redis.

#### A-008 — Migración commercial fields en VPS

- **Evidencia:** Gate G0.1 documenta migrate `int_mensajes` (2026-07-04); migración `2026_07_06_120000_add_commercial_fields` posterior — estado en VPS no verificable desde automation.
- **Impacto:** Si no migrada, endpoints `POST /account/status` y campos comerciales fallan. Si migrada sin backfill, tenants activos quedan como `commercial_status=demo`.
- **Recomendación humana:** Confirmar `php artisan migrate:status` en VPS y backfill de tenants no-demo.
