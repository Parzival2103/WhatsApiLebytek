### Detalle (medio/alto/crítico)

#### A-001 — CI roto (PHP 8.3 vs Symfony 8.1)

- **Evidencia:** Run [29183105951](https://github.com/Parzival2103/WhatsApiLebytek/actions/runs/29183105951) — 19 conflictos de plataforma; ej. `symfony/http-foundation v8.1.1 requires php >=8.4.1`. `composer.json` declara `"php": "^8.3"`.
- **Impacto:** Ningún push/PR a `main` pasa CI; regresiones no detectadas automáticamente.
- **Recomendación humana:** Actualizar `.github/workflows/tests.yml` a `php-version: '8.4'` **o** regenerar `composer.lock` con restricciones Symfony 7.x compatibles con 8.3. Alinear también `composer.json` `require.php`.

#### A-002 — Webhooks Green API incompatibles con middleware actual

- **Evidencia:**
  - `ProvisionGreenInstanceJob` configura `'webhookUrlToken' => config('services.green_api.webhook_secret')` → Green API envía `Authorization: Bearer …` ([docs Green API](https://greenapi.com/en/docs/api/receiving/technology-webhook-endpoint/)).
  - `VerifyWebhookSignature` exige `X-Webhook-Signature` = `hash_hmac('sha256', body, secret)`.
  - `WebhookIdempotency` exige header `X-Event-Id` (no estándar Green API).
  - Tests en `WebhookVerificationTest.php` validan el contrato HMAC custom, no el flujo Green API real.
- **Impacto:** Instancias provisionadas no sincronizarán estado vía webhook; posible desincronización `authorized`/`waiting_qr` en producción.
- **Recomendación humana:** Implementar guard dual: validar `Authorization: Bearer` contra `WEBHOOK_SECRET` para tráfico Green API; mantener HMAC solo si hay consumidor interno. Idempotencia derivada de campos del payload (`idMessage`, hash de body) si no hay `X-Event-Id`.

#### A-003 — Horizon provisioning en producción

- **Evidencia:** `supervisor-provisioning` en `defaults` (cola `provisioning`, timeout 120s); `environments.production` no lo lista (Horizon hace merge con defaults, pero sin `maxProcesses` dedicado).
- **Impacto:** Jobs `ProvisionGreenInstanceJob` / `DeleteGreenInstanceJob` podrían procesarse con solo 2 workers default; cuello de botella bajo carga.
- **Recomendación humana:** Verificar `php artisan horizon:status` en VPS; añadir override production para `supervisor-provisioning` si hace falta escalar.

#### A-004 — Persistencia webhooks incompleta

- **Evidencia:** Tabla `int_webhooks` creada; controller solo actualiza `int_instancias` en memoria para `stateInstanceChanged`.
- **Impacto:** Sin auditoría de eventos, sin inbound messages, sin replay.
- **Recomendación humana:** Seguir spec `docs/superpowers/specs/2026-07-01-integration-phase2-3-design.md`.
