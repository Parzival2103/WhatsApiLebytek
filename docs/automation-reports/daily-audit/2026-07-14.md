### Detalle (medio/alto/crítico)

#### A-001 — CI roto por drift PHP / Symfony

- **Evidencia:** `gh run view 29307791927 --log-failed` → `symfony/http-foundation v8.1.1 requires php >=8.4.1 -> your php version (8.3.32) does not satisfy that requirement.` `composer.json` exige `"php": "^8.3"`.
- **Impacto:** Ningún push a `main` pasa tests/build en CI desde al menos el 13-Jul. Regresiones no detectadas automáticamente.
- **Recomendación humana:** Decidir estrategia: (a) bump CI + `composer.json` a PHP 8.4 y validar VPS, o (b) `composer update` con constraint Symfony ^7.4 para mantener PHP 8.3.

#### A-002 — Webhooks Green API incompatibles con middleware

- **Evidencia:**
  - `ProvisionGreenInstanceJob` → `'webhookUrlToken' => config('services.green_api.webhook_secret')`
  - `VerifyWebhookSignature` → exige `X-Webhook-Signature` = `hash_hmac('sha256', body, WEBHOOK_SECRET)`
  - `WebhookIdempotency` → exige `X-Event-Id` (Green API no documenta este header)
  - Tests (`WebhookVerificationTest`) solo cubren HMAC sintético, no payload Green API real
- **Impacto:** Instancias provisionadas no sincronizan estado (`authorized`/`waiting_qr`) vía webhook; mensajes entrantes no procesados. Posible dependencia de polling manual o jobs alternativos.
- **Recomendación humana:** Implementar adaptador dual: validar `Authorization: Bearer {webhookUrlToken}` según Green API **o** HMAC si se acuerda extensión; relajar/generar `X-Event-Id` desde hash del body si Green no lo envía; smoke test con instancia real.

#### A-003 — Horizon provisioning sin tuning production

- **Evidencia:** `config/horizon.php` — `environments.production` solo override `supervisor-default`, `supervisor-transactional`, `supervisor-campaigns`. `supervisor-provisioning` queda con `maxProcesses: 2`.
- **Impacto:** Picos de provisioning (demos, onboarding) pueden encolar más de lo deseado.
- **Recomendación humana:** Añadir override production para `supervisor-provisioning` (p. ej. `maxProcesses: 4`) y validar con métricas Horizon.

#### A-004 — int_webhooks sin uso

- **Evidencia:** Migración `2026_07_02_100001_create_int_webhooks_table.php` existe; ningún modelo/controlador inserta filas. `IncomingWebhookController` no audita eventos.
- **Impacto:** Sin trazabilidad de webhooks; deduplicación solo en cache Redis 24h (`WebhookIdempotency`), no durable.
- **Recomendación humana:** Persistir antes de procesar (spec fase 2.8).

#### A-005 — Cobertura tests instancias/webhook estado

- **Evidencia:** `InstanceProvisioningTest` cubre `POST /instances` con Bus fake; no hay tests para index/qr/destroy. `WebhookVerificationTest` no prueba `stateInstanceChanged` actualizando `int_instancias`.
- **Impacto:** Regresiones en flujos demo/QR/delete no detectadas sin CI verde.
- **Recomendación humana:** Añadir Feature tests mínimos cuando CI esté operativo.
