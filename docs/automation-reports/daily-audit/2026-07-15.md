### Detalle (medio/alto/crítico)

#### A-001 — Webhooks Green API incompatibles con middleware HMAC

- **Evidencia:**
  - `ProvisionGreenInstanceJob` configura `webhookUrlToken` → `WEBHOOK_SECRET`
  - `VerifyWebhookSignature` valida `X-Webhook-Signature` (HMAC SHA-256 del body)
  - `WebhookIdempotency` exige `X-Event-Id`
  - [Green API docs](https://greenapi.com/en/docs/api/receiving/technology-webhook-endpoint/): envía `Authorization: Bearer <token>`, sin headers custom
  - Tests (`WebhookVerificationTest`) solo cubren esquema HMAC interno
- **Impacto:** instancias pueden permanecer en `waiting_qr` tras escanear QR; flujo demo→pago incompleto en ops reales
- **Recomendación humana:** diseñar adapter dual (Bearer + idempotencia por payload Green) antes de confiar en webhooks en VPS

#### A-002 — Coordinación deploy activate-plan

- **Evidencia:** PR #14–#15 en api; Framework commit `2026-07-15` mergeó `feature/backoffice-api-integration` con `activatePlan()` y hardening membership
- **Impacto:** error SQL/runtime si `meta` no existe; tokens demo no revocados si se usa PATCH en lugar de activate-plan
- **Recomendación humana:** seguir checklist en `docs/superpowers/plans/2026-07-14-plan-activation-closure.md` (Task 4 — solo humano)

#### A-003 — Cobertura tests instances/webhook

- **Evidencia:** `InstanceProvisioningTest` cubre POST/store y permisos; no hay tests para index, qr, destroy ni `stateInstanceChanged`
- **Impacto:** regresiones en endpoints expuestos al back-office sin detección en CI
- **Recomendación:** añadir Feature tests en próximo PR de instances
