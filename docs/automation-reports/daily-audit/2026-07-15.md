### Detalle (medio/alto)

#### A-002 — Deploy coordinado activate-plan + webhooks

- **Evidencia:** PRs #14, #15, #20 en `main`; Framework merge PR #5 (`activatePlan`, membership authorize) 2026-07-15.
- **Impacto:** Sin `migrate` en VPS, `activate-plan` falla al escribir `meta`. Sin deploy PR #20, webhooks Green siguen rechazados.
- **Recomendación humana:** Seguir checklist Issue #17 + smoke webhook `stateInstanceChanged` tras deploy.

#### A-003 — PATCH tenant bypass activate-plan

- **Evidencia:**

```22:28:app/Http/Requests/Api/V1/UpdateTenantRequest.php
            'commercialStatus' => ['sometimes', 'string', 'in:demo,active,past_due,cancelled'],
            'planSlug' => ['sometimes', 'string', 'max:50'],
            'planName' => ['sometimes', 'string', 'max:150'],
```

`TenantProvisioningService::update` aplica estos campos sin revocar tokens Sanctum ni escribir `meta.activation`.

- **Impacto:** Plataforma podría elevar límites o estado comercial sin rotación de token ni trazabilidad de billing.
- **Recomendación humana:** Restringir campos sensibles en PATCH o redirigir a `activate-plan`; añadir test de regresión.

#### A-004 — Webhook sin throttle

- **Evidencia:** Grupo `v1/webhooks` solo tiene `webhook.signature` + `webhook.idempotency`; API v1 usa `throttle:api` (60/min).
- **Impacto:** Ataque de volumen contra endpoint público; cada request valida HMAC/Bearer + cache Redis.
- **Recomendación humana:** Añadir `throttle:webhooks` (p.ej. 120/min por IP) en `AppServiceProvider`.
