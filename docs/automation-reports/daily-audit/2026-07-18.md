### Detalle (medio/alto)

#### A-001 — Deploy coordinado pendiente

- **Evidencia:** Issue #17 abierto; último commit `54d5bf0` (2026-07-16); `docs/DEPLOY.md` requiere migrate + horizon restart tras pull.
- **Impacto:** Framework con `activatePlan()` puede fallar si columna `meta` no existe en prod; endpoints cancel/reactivate inaccesibles hasta deploy.
- **Recomendación humana:** Ejecutar checklist VPS en `docs/DEPLOY.md` § Actualización; smoke `activate-plan`, `cancel-commercial`, `reactivate-commercial`.

#### A-002 — PATCH bypass activate-plan

- **Evidencia:** `UpdateTenantRequest` acepta campos comerciales; `TenantProvisioningService::update()` aplica sin revocar tokens; `ActivatePlanService` es el único flujo con rotación + `meta.activation`.
- **Impacto:** Elevación de límites plan-aware sin trazabilidad; posible bypass de billing desde Framework vía `updateTenant()`.
- **Recomendación humana:** Restringir PATCH a `name`/`isActive` o prohibir campos comerciales; añadir test Feature (ver Issue #21).

#### A-003 — Webhook sin throttle

- **Evidencia:** Grupo `v1/webhooks` usa `webhook.signature` + `webhook.idempotency` únicamente; API autenticada usa `throttle:api` (60/min).
- **Impacto:** Superficie de abuso si atacante obtiene o adivina secret; volumen alto de requests antes de rechazo 401.
- **Recomendación humana:** Añadir `throttle:webhooks` (p.ej. 120/min por IP) en `AppServiceProvider`.
