### Detalle (medio/alto)

#### A-001 — Deploy coordinado pendiente

- **Evidencia:** Issue #17 abierto; post-#29 además hace falta Horizon con `supervisor-webhooks` y cron `* * * * * php artisan schedule:run` (documentado en `docs/DEPLOY.md`).
- **Impacto:** Endpoints y jobs nuevos pueden no estar activos en prod; watcher de webhooks no corre sin scheduler.
- **Recomendación humana:** Ejecutar checklist VPS; smoke activate-plan / cancel / reactivate; confirmar cola `webhooks` en Horizon UI.

#### A-002 — PATCH bypass activate-plan

- **Evidencia:** Issue #21; `UpdateTenantRequest` acepta campos comerciales; `ActivatePlanService` es el flujo con rotación + `meta`.
- **Impacto:** Cambio de plan/límites sin trazabilidad ni rotación de token.
- **Recomendación humana:** Restringir PATCH a campos no comerciales o forzar el flujo `activate-plan`.

#### A-003 — Webhook sin throttle

- **Evidencia:** `Route::prefix('v1/webhooks')->middleware(['webhook.signature'])` sin throttle.
- **Impacto:** Superficie DoS si se filtra/adivina el secret.
- **Recomendación humana:** `throttle:webhooks` por IP (p. ej. 120/min).

#### A-006 — Drift Framework client

- **Evidencia:** Audits #26+#28; api expone cancel/reactivate; Framework no envuelve esos métodos.
- **Impacto:** Back-office no puede operar el ciclo comercial vía cliente tipado.
- **Recomendación humana:** Añadir métodos en `LebytekApiClient` en la feature branch del Framework (sin merge a `main` Framework salvo orden explícita).
