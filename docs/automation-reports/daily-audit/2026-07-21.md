### Detalle (medio/alto)

#### A-001 — Deploy VPS pendiente de PR #29

- **Evidencia:** Último commit `main` = merge PR #29 (`9e62475`, 2026-07-18). Cambios: `IncomingWebhookController` persist-then-dispatch, `ProcessWebhookJob`, supervisor `webhooks` en `config/horizon.php`, `Schedule::command('webhooks:check-unprocessed')` en `routes/console.php`, eliminación middleware cache-only `WebhookIdempotency`.
- **Impacto:** Sin deploy, eventos webhook pueden perderse (black hole); instancias no sincronizan `stateInstanceChanged`; alertas de backlog inactivas.
- **Recomendación humana:** Ejecutar checklist `docs/DEPLOY.md` (pull, composer, npm build, migrate si aplica, cache, **restart Horizon**). Verificar cron `* * * * * php artisan schedule:run`. No requiere `integration:issue-waapi-token` ni migración nueva (tabla `int_webhooks` ya existía).

#### A-002 — PATCH bypass activate-plan (Issue #21)

- **Evidencia:** `UpdateTenantRequest` valida `planSlug`, `commercialStatus`, `messagesMonthlyLimit`. `TenantProvisioningService::update()` escribe directo. `ActivatePlanService` es el único flujo con rotación de token.
- **Impacto:** Inconsistencia billing/límites; bypass de trazabilidad en integración Framework.
- **Recomendación:** Resolver vía Issue #21 (restringir PATCH o alinear auditoría).

#### A-003 — Webhook sin rate limit

- **Evidencia:** Grupo API autenticada usa `throttle:api`; webhooks usan solo `webhook.signature`.
- **Impacto:** Abuso de volumen post-autenticación; presión en BD (`int_webhooks` INSERT) y cola Redis.
- **Recomendación:** Añadir limiter en `RouteServiceProvider` / `bootstrap/app.php` y aplicar a ruta incoming.
